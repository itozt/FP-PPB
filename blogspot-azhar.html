1. Deskripsi Aplikasi

MovFlix adalah aplikasi katalog film (movie catalogue) modern yang memungkinkan pengguna menjelajah, mencari, dan menonton trailer film terbaru langsung di dalam aplikasi. Seluruh data film diambil secara real-time dari TMDB (The Movie Database) API, sehingga daftar film yang ditampilkan selalu mengikuti perkembangan terkini. Aplikasi ini dibangun sepenuhnya menggunakan Jetpack Compose, framework UI declarative terbaru dari Android yang memberikan pengalaman pengguna yang responsif, mulus, dan sinematik.
Dengan antarmuka bertema gelap yang elegan, MovFlix menampilkan film populer melalui hero slider yang bergeser otomatis, baris kategori seperti Now Playing, Popular, dan Top Rated, hingga halaman detail lengkap dengan pemutaran trailer YouTube secara full-screen. Pengguna dapat berpindah antar layar Home, Search, dan Profile dengan navigasi swipe yang intuitif menggunakan HorizontalPager.
Aplikasi ini juga dilengkapi sistem autentikasi lokal (register, login, dan masuk sebagai guest) serta fitur watchlist per-akun yang tersimpan secara offline di perangkat. MovFlix dikembangkan sebagai pemenuhan evaluasi Final Project mata kuliah Pemrograman Perangkat Bergerak.
Bahasa: Aplikasi dikembangkan menggunakan Kotlin dengan antarmuka berbahasa Indonesia agar mudah dipahami pengguna lokal. Minimum SDK: Aplikasi kompatibel dengan Android 7.0 (API Level 24) dan versi yang lebih baru, sehingga menjangkau pengguna yang luas.

2. Fitur-Fitur Utama Aplikasi

2.1 Autentikasi Lokal
Fitur: Pengguna dapat mendaftar (register) dan masuk (login) menggunakan email dan password, atau memilih Masuk sebagai Guest untuk menjelajah aplikasi tanpa membuat akun terlebih dahulu.
Keamanan: Password tidak pernah disimpan dalam bentuk asli. Sistem menyimpan password yang sudah diamankan menggunakan teknik hashing SHA-256 + salt secara lokal melalui Room. Salt acak dibuat untuk setiap pengguna, sehingga dua password yang sama tetap menghasilkan hash yang berbeda.
Session: Status login pengguna disimpan menggunakan SharedPreferences, sehingga pengguna tetap masuk meskipun aplikasi ditutup dan dibuka kembali.
2.2 Navigasi Cepat Berbasis Swipe
Fitur: Transisi antara tiga layar utama — Home, Search, dan Profile — dapat dilakukan dengan mengusap layar (swipe gesture) secara horizontal, tanpa harus selalu menekan tombol navigasi.
Implementasi: Menggunakan HorizontalPager dari Jetpack Compose yang tersinkron dengan bottom navigation bar. Saat pengguna menggeser layar, indikator tab di bawah ikut berpindah, begitu pula sebaliknya.
Keuntungan: Pengalaman navigasi yang lebih cepat, modern, dan terasa natural seperti aplikasi streaming populer.
2.3 Beranda (Home) Dinamis
Hero Slider Otomatis: Bagian atas Home menampilkan slider film trending yang bergeser otomatis dan tak terbatas (infinite loop). Saat pengguna menyentuh slider, pergeseran otomatis akan berhenti sementara (interruptibility), memberi pengguna kendali penuh.
Kategori Film: Di bawah hero slider terdapat baris-baris film yang dikelompokkan berdasarkan kategori, yaitu Now Playing (sedang tayang), Popular (populer), dan Top Rated (rating tertinggi).
Collapsing Top Bar: Saat pengguna menggulir (scroll) ke bawah, top bar akan menyusut secara halus untuk memberi ruang lebih luas bagi konten film.
2.4 Pencarian Cerdas (Search)
Pencarian Debounced: Pencarian film dilakukan secara otomatis sambil mengetik, tanpa perlu menekan tombol submit. Permintaan ke server ditahan sejenak (debounce) hingga pengguna berhenti mengetik, sehingga lebih hemat data dan responsif.
Filter Genre: Hasil pencarian dapat disaring berdasarkan genre film, memudahkan pengguna menemukan film sesuai selera.
2.5 Detail Film & Trailer
Halaman Detail: Saat pengguna memilih sebuah film, aplikasi menampilkan halaman detail lengkap berisi sinopsis, rating, durasi (runtime), tagline, status, dan daftar genre.
Pemutaran Trailer: Pengguna dapat menonton trailer YouTube langsung di dalam aplikasi secara full-screen, tanpa harus berpindah ke aplikasi lain. Pemutaran ini menggunakan WebView dengan YouTube iframe embed.
2.6 Watchlist Per-Akun
Simpan Film Favorit: Pengguna dapat menyimpan film ke dalam watchlist untuk ditonton nanti. Watchlist ini terikat pada akun masing-masing, sehingga setiap pengguna memiliki daftarnya sendiri yang terpisah.
Tersimpan Offline: Data watchlist disimpan secara lokal menggunakan Room Database, sehingga tetap dapat diakses tanpa koneksi internet.
Pembatasan Guest: Pengguna yang masuk sebagai guest diarahkan untuk login terlebih dahulu sebelum dapat menyimpan film ke watchlist.
2.7 Estetika Material Design 3
Tampilan Sinematik: Aplikasi menggunakan tema gelap (dark theme) yang nyaman untuk konten film. Saat data sedang dimuat, ditampilkan efek shimmer skeleton agar pengguna mengetahui status sistem (visibility of system status).
Splash Screen: Aplikasi diawali dengan splash screen berlogo MovFlix, memberikan kesan profesional saat pertama kali dibuka.

3. Arsitektur Aplikasi

MovFlix menggunakan arsitektur MVVM (Model-View-ViewModel) dengan prinsip Single Source of Truth pada lapisan Repository. Arsitektur ini memisahkan logika bisnis dari antarmuka pengguna, sehingga kode menjadi lebih terstruktur, testable, dan mudah di-maintain. Lapisan Repository menjadi satu-satunya sumber kebenaran data, baik yang berasal dari API maupun dari database lokal.
3.1 Penjelasan Setiap Layer
Layer Deskripsi Tanggung Jawab
UI Layer Lapisan presentasi yang menampilkan antarmuka kepada pengguna. Menggunakan Jetpack Compose untuk UI deklaratif dan Material 3 untuk design system modern, serta Navigation Compose untuk perpindahan antar layar. Menampilkan data, menangkap input pengguna, navigasi antar layar
ViewModel Lapisan yang mengelola state (kondisi) layar dan logika presentasi. Menggunakan StateFlow untuk reactive state management yang efisien. Mengelola state UI, memanggil repository, menyediakan data ke UI
Repository Lapisan abstraksi yang menjadi Single Source of Truth. MovieRepository menjembatani data dari TMDB API dan watchlist lokal, sedangkan AuthRepository menangani autentikasi dan session. Menyediakan data terpadu ke ViewModel, logika bisnis tingkat tinggi
Data Layer Lapisan sumber data. Bagian remote menggunakan Retrofit + OkHttp + Gson untuk mengakses TMDB API; bagian local menggunakan Room Database (SQLite) untuk watchlist & akun, serta SharedPreferences untuk session. Mengambil data dari jaringan, menyimpan & membaca data lokal
3.2 Dependency Injection
Aplikasi menggunakan sistem Dependency Injection manual melalui ServiceLocator, sebuah object Kotlin yang bertanggung jawab membuat dan menyediakan instance dari Retrofit, Room Database, serta repository. Pendekatan ini dipilih agar ringan dan sesuai dengan skala proyek, tanpa overhead library seperti Hilt atau Dagger. Instance repository dibuat secara lazy dan singleton (thread-safe) sehingga hanya dibuat satu kali dan dipakai bersama di seluruh aplikasi.

5.2 AppNavigation — Navigation Graph
AppNavigation mendefinisikan seluruh alur perpindahan layar menggunakan NavHost dari Navigation Compose, lengkap dengan animasi transisi (fade dan slide). Destinasi awal adalah Splash, kemudian diarahkan ke Login atau Main bergantung pada status session.
AppNavigation() Composable
@Composable
fun AppNavigation(
    repository: MovieRepository,
    authRepository: AuthRepository
) {
    val navController = rememberNavController()
    val session by authRepository.session.collectAsState()
    val isGuest = session?.isGuest == true

    NavHost(
        navController    = navController,
        startDestination = Screen.Splash.route
    ) {
        composable(Screen.Splash.route) {
            SplashScreen(onTimeout = {
                val loggedIn = authRepository.session.value != null
                val target = if (loggedIn) Screen.Main.route else Screen.Login.route
                navController.navigate(target) {
                    popUpTo(Screen.Splash.route) { inclusive = true }
                }
            })
        }
        composable(Screen.Login.route)    { /* LoginScreen */ }
        composable(Screen.Register.route) { /* RegisterScreen */ }
        composable(Screen.Main.route)     { /* MainScreen */ }
        composable(Screen.Detail.route)   { /* DetailScreen */ }
    }
}
Penjelasan:
  • navController = rememberNavController(): Membuat controller yang mengatur perpindahan antar destinasi (route).
  • session = authRepository.session.collectAsState(): Mengamati session pengguna secara reaktif. Setiap perubahan login/logout akan langsung memengaruhi UI.
  • isGuest: Menandai apakah pengguna sedang masuk sebagai guest, untuk membatasi fitur tertentu seperti watchlist.
  • startDestination = Screen.Splash.route: Aplikasi selalu dimulai dari Splash Screen.
  • Conditional Navigation: Setelah splash, jika sudah ada session pengguna diarahkan ke Main; jika belum, diarahkan ke Login. popUpTo(... inclusive = true) memastikan layar splash dihapus dari back stack.
  • Daftar Route: Splash, Login, Register, Main, dan Detail (dengan argumen movieId).

5.5 ServiceLocator — Dependency Injection
ServiceLocator menyatukan pembuatan seluruh dependency: Retrofit (untuk TMDB API), Room Database, dan repository. Token autentikasi TMDB disisipkan otomatis pada setiap request melalui OkHttp Interceptor.
ServiceLocator (ringkas)
object ServiceLocator {
    private const val BASE_URL = "https://api.themoviedb.org/3/"

    fun provideRepository(context: Context): MovieRepository {
        return repository ?: synchronized(this) {
            repository ?: buildRepository(context).also { repository = it }
        }
    }

    private fun buildOkHttpClient(): OkHttpClient {
        val authInterceptor = Interceptor { chain ->
            val request = chain.request().newBuilder()
                .header("Authorization", "Bearer ${BuildConfig.TMDB_BEARER_TOKEN}")
                .header("accept", "application/json")
                .build()
            chain.proceed(request)
        }
        return OkHttpClient.Builder()
            .addInterceptor(authInterceptor)
            .build()
    }
}
Penjelasan:
  • object ServiceLocator: Singleton yang dapat diakses dari mana saja di aplikasi.
  • provideRepository (double-checked locking): Membuat instance repository hanya sekali secara thread-safe, lalu menggunakannya kembali pada pemanggilan berikutnya.
  • authInterceptor: Menyisipkan header Authorization berisi Bearer token TMDB ke setiap request, sehingga API key tidak perlu ditulis di tiap pemanggilan.
  • BuildConfig.TMDB_BEARER_TOKEN: Token diambil dari konfigurasi build, bukan ditulis langsung (hardcode) di dalam kode.

6. Alur Eksekusi Aplikasi

Berikut adalah alur lengkap eksekusi aplikasi dari saat diluncurkan hingga siap digunakan:

7. Interaksi User dan Event Flow

Aplikasi menggunakan event-driven architecture di mana interaksi pengguna di UI memanggil callback yang terhubung ke ViewModel, lalu ViewModel memanggil Repository. Berikut beberapa contoh alur (flow) yang terjadi dalam aplikasi:
🔐 User Login / Register
Flow: User mengisi email & password di LoginScreen → menekan tombol "Masuk" → AuthViewModel memanggil AuthRepository.login() → password diverifikasi dengan PasswordHasher (SHA-256 + salt) terhadap data di Room → jika cocok, session disimpan via SessionManager → AppNavigation otomatis mengarahkan ke Main. Pada register, akun baru dibuat di Room lalu langsung login.
🎬 User Menjelajah Film di Home
Flow: HomeScreen tampil → HomeViewModel memanggil MovieRepository (getTrendingMovies, getNowPlayingMovies, dst) → Repository memanggil TMDB API via Retrofit → hasil dipetakan dari DTO ke model domain → StateFlow di-update → UI recompose menampilkan hero slider dan baris kategori. Hero slider bergeser otomatis dan berhenti saat disentuh.
🔍 User Mencari Film
Flow: User mengetik kata kunci di SearchScreen → SearchViewModel menerapkan debounce (menunggu pengguna berhenti mengetik) → memanggil MovieRepository.searchMovies() → hasil ditampilkan dan dapat disaring dengan filter genre → UI recompose menampilkan daftar film yang relevan.
▶️ User Membuka Detail & Menonton Trailer
Flow: User mengetuk sebuah MovieCard → navController berpindah ke route Detail dengan argumen movieId → DetailViewModel memanggil MovieRepository.getMovieDetail() (detail + videos) → UI menampilkan sinopsis, rating, durasi, dan genre → saat user menekan trailer, YouTubeTrailerPlayer memutar trailer YouTube secara full-screen di dalam aplikasi.
⭐ User Menyimpan Film ke Watchlist
Flow: User menekan tombol watchlist di halaman detail → jika pengguna adalah guest, diarahkan untuk login terlebih dahulu → jika sudah login, MovieRepository.addToWatchlist() menyimpan film ke Room dengan composite key (id + userId) → daftar watchlist (Flow) di-update otomatis dan tampil di halaman Profile, terpisah untuk setiap akun.
👤 User Membuka Profile & Logout
Flow: User berpindah ke tab Profile → ProfileViewModel menampilkan nama, email, dan daftar watchlist milik akun → saat user menekan Logout, AuthRepository.logout() menghapus session via SessionManager → AppNavigation otomatis kembali ke layar Login.
